# ADR (черновик): WireGuard-сеть VDS ↔ pve ↔ раннер для CI

- Статус: предложено
- Дата: 2026-10-09

## Контекст

Self-hosted раннера `ops` нет. Cloudflare Tunnel без Zero Trust давал `501` на POST к API Proxmox и обрывы SSH.
Куплен VDS Selectel `zelda` (`161.104.47.226`), будущий `edge-0`.

## Решение

- WireGuard-сеть `10.99.0.0/24`, хаб — VDS (`10.99.0.1`, `51820/udp`).
- `pve` (`10.99.0.2`) — постоянный пир, маршрут в `192.168.100.0/24`, `MASQUERADE` в `vmbr0`.
- Раннер GitHub (`10.99.0.3`) — пир на время job, ключ в Environment `images`. На VDS раннеру разрешены только `192.168.100.10:8006` и `192.168.100.250:22`.
- Сборка — `ubuntu-24.04` (GitHub-hosted), только из `master`, job-ы последовательны.
- TLS к Proxmox проверяется по CA Proxmox (`PROXMOX_CA_PEM`).
- SSH к VDS — `root`, порт `1111`, только ключи.

## Последствия

- Proxmox и ВМ не опубликованы; в интернете только `1111/tcp` и `51820/udp` VDS.
- ВМ → `10.99.0.0/24` требует маршрута через `192.168.100.10` (Ansible для узлов кластеров).
- Риск блокировки WireGuard на маршруте раннер → РФ; план B — AmneziaWG.
- Дальше — Headscale на этом VDS вместо ручного WireGuard.

## Альтернативы

- Cloudflare Tunnel: `501` на POST, нестабильный SSH.
- SSH-бастион с пробросом портов: работает, но только для фиксированных адресов; нет общей сети.
- Self-hosted раннер на VDS: код CI исполняется на VDS.
